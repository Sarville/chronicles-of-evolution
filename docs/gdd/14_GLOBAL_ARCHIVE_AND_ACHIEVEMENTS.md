# Хроники Эволюции — глобальный Архив и ачивки

**Версия:** 1.0
**Статус:** canonical mechanic / точный список ачивок и веса provisional
**Authority:** `docs/DECISIONS_ACT_STRUCTURE.md` (`ACT-011`). Этот документ
превращает решение `ACT-011` в конкретный контракт для UI/сохранений.

**Отношение к другим документам:** не вводит новую валюту. Использует уже
существующие примитивы — Archive Fragments (AF, `docs/gdd/10_META_PROGRESSION.md`
§2), Chronicle, Archive Tree (`AR01…AR12`), `meta.endings.*`
(`docs/scenario/05_NARRATIVE_FLAGS.md`). Ачивка — это булев флаг поверх уже
существующего состояния, не отдельный трекер.

---

# 1. Зачем нужен этот документ

`ACT-009`/`ACT-010` требуют финиш-лайн для «бесконечного» Акта 3: игрок
должен иметь конечную, честную цель «собрать всё», которая когда-нибудь
физически достигает 100%, даже если числовые валюты Акта 3 растут без
верхней границы. Этот документ определяет, что именно считается «всем»,
как это визуализируется и что происходит на 100%.

---

# 2. Archive Completion — определение

Один показатель `0–100%`, видимый игроку в отдельном экране «Архив»
(не путать с внутриигровым понятием Архива-персонажа). Считается как:

```text
Archive Completion % = (открытые ачивки) / (все ачивки, существующие
                        на данный момент в содержимом игры) × 100
```

Знаменатель фиксирован и известен заранее (это список ачивок из §4, не
бесконечная числовая шкала). Рост currency Акта 3 (Plasmid/Phage/Dark/
Harmony/Artifact/Supercoiled/AICore-эквиваленты) сам по себе не даёт
прогресса Completion — только достижение конкретных порогов/событий с этими
системами (§4.4) засчитывается.

**Жёсткое правило:** Completion никогда не откатывается назад ни одним
reset'ом (ни `T1–T5`, ни `P`, ни Act 3 universe reset) — ачивка, однажды
открытая, остаётся открытой навсегда, как и AF. Это тот же idempotent-принцип,
что уже действует для AF (`10_META_PROGRESSION.md` §3).

---

# 3. Веса по актам

Act 1/Act 2/Act 3 не считаются поровну — прохождение Акта 1 длится ~3–4ч и
имеет конечный, короткий список исходов; Акт 3 в принципе бесконечен по
контенту (новые race/trait комбинации, universes, challenge modifiers).
Если считать 1 ачивка = 1 пункт без весов, Act 3 обесценивает всё, что было
раньше, и 100% становится недостижимым при любом разумном темпе игры.

Provisional split (уточняется после реализации Акта 2/3, как и любой другой
числовой таргет в проекте):

```text
Act 1 (T1–T5, все исходы/варианты)      — 30% от итоговых 100%
Act 2 (P1–P3, все три + unified reveal) — 15%
Act 3, story-gated (§4.4 milestones)     — 20%
Act 3, content-collection (§4.5)         — 30%
Grand finale (100%-gated scene, ACT-010) — не входит в сумму, это сам факт
  достижения 100% выше, не отдельный пункт с весом
```

Внутри каждого блока ачивки весят поровну (нет отдельных «редких»/
«платиновых» ачивок с бо́льшим весом — это усложнение, которое ACT-011
сознательно не вводит: 1 ачивка = 1 равная доля своего блока).

# 4. Категории ачивок

## 4.1 Story / Chronicle (Act 1)

По одной ачивке за первое достижение каждого ending'а хотя бы раз за всю
мета-историю аккаунта (не за конкретный прогон):

```text
ENDING_BLIGHT достигнут       (Мор, T1)
ENDING_CATACLYSM достигнут    (Катаклизм, T2)
ENDING_FRACTURE достигнут     (Раскол, T3)
ENDING_OVERLOAD достигнут     (Авария, T4)
ENDING_ASH достигнут          (Пепел, T5 — обязателен по сюжету, но всё
                                равно считается отдельной ачивкой)
```

## 4.2 Variant / subtype (Act 1)

По одной ачивке за каждый уникальный `chapterN_subtype`, зафиксированный
хотя бы раз (`docs/scenario/05_NARRATIVE_FLAGS.md` §5A) — например все три
subtype `Мор` (`blight_isolated`/`blight_unified`/`blight_early_medicine`) и
аналогично для `T2–T4`. Точный список subtype ID и их число — источник
истины `docs/scenario/06_ENDINGS_COPY.md`, не дублируется здесь во
избежание рассинхрона.

## 4.3 Discovery (Act 1 + Act 2)

Ачивка за первое срабатывание каждой карточки процедурных колод: `early_biology`
(`EV-RNA-RESONANCE`, `EV-DNA-TRACE`, ...) и `t5_synthesis`
(все 8 `EV-T5-ECHO-*`, `docs/gdd/13_ACT_ONE_CHAPTERS.md` §7.3). Это
единственная категория, требующая удачи/повторных прогонов, а не просто
чистого прохождения — сознательно: даёт причину переигрывать уже пройденные
главы, не вводя отдельную reward-валюту сверх Completion.

## 4.4 Act 2 / Act 3 story-gated

```text
P1 завершён хотя бы раз (любой исход)
P2 завершён хотя бы раз
P3 завершён хотя бы раз
Act 2 unified reveal увиден (фактически = любой первый P, но считается
  отдельно как сюжетная веха, не дубликат — см. ACT-008)
Act 3 достигнут (первая точка входа)
Первый Act 3 reset пройден = first-reset finale увиден (ACT-009 п.2)
```

## 4.5 Act 3 content-collection

Конечный список — canonical source of truth теперь
`docs/gdd/15_ACT_THREE_SYSTEMS.md` §7, не этот документ. Свод (2026-09-17):

```text
races (15_...md §3.2)                         10
prestige currency, первая трата (§4.2)         7
universe-типы, первое прохождение (§5.2)       8
challenge-модификаторы (§5.3)                  6
ARPA мегапроекты (§6.2)                        8
-------------------------------------------------
итого Act 3 content-collection                39
```

§3 фиксирует **долю** (30% от 100%), не число ачивок, поэтому будущее
расширение списка не ломает уже пройденный Completion — знаменатель
пересчитывается, проценты игрока могут временно чуть просесть при выходе
патча с новым контентом, тем же образом, каким это уже принято для
достижений в любой live-игре (явно фиксируется как допустимое поведение,
чтобы не потребовалось отдельное решение позже).

# 5. Экран «Архив» (Archive Log)

Не таблица/чек-лист и не трофейная витрина — физическая метафора: полки
хранилища, заполняющиеся фрагментами по мере открытия ачивок, тем же
визуальным языком, что уже закреплён за Archive Fragments/Chronicle
(диорама/архивная эстетика проекта, `docs/art/00_ART_DIRECTION.md`).

```text
макет:
- общий % Completion крупно сверху (число + визуальное заполнение полки)
- пять групп-полок: T1–T5 / P1–P3 / Discovery / Act 3 story / Act 3 collection
- каждая ачивка — один "фрагмент" на полке: тусклый контур, если не открыт;
  заполненный + короткая Chronicle-строка, если открыт
- открытие ачивки не даёт modal/popup поверх геймплея — тихая toast-нотификация
  (не мешает текущему прогону), полная деталь доступна только на самом экране
```

Хард-правило: как и в остальном проекте, экран не должен спойлерить
subtype/entry, который игрок ещё не встретил — закрытые ячейки показывают
только факт существования (силуэт), не текст.

# 6. Гейты

```text
Act 3 first-reset finale (ACT-009 п.2)  — не требует Completion, привязан
  к событию "первый reset внутри Act 3"
Grand finale (ACT-010)                   — требует ровно 100% Completion,
  проверяется при каждом изменении Completion (не только на reset), сцена
  срабатывает в момент пересечения порога
```

Grand finale — одноразовая сцена (см. `ACT-010`, копия —
`docs/scenario/02_ACT2_ACT3_SCRIPT.md` §5); повторный показ невозможен,
факт просмотра — отдельный persistent-флаг
(`meta.archive.grand_finale_seen`), не пересчитывается из Completion задним
числом.

  (§4.5) больше не открыт.

  таргеты проекта, подтверждаются плейтестом/телеметрией.
- Формат toast-нотификации (мобайл-специфика: положение, чтобы не

  здесь.
