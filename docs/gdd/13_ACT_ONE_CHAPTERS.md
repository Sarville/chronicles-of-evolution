# 1. Зачем нужен этот документ

`DECISIONS_ACT_STRUCTURE.md` (ACT-002, скорректировано 2026-09-18) фиксирует:
вместо одного 105–180-минутного забега RNA→Ash игрок проходит **пять
попыток, каждая — полный replay с RNA** (~3–4 часа суммарно), с растущим
бюджетом (`T1` ~20 мин … `T5` ~40 мин) и растущей era cutoff-точкой коллапса.
Нет отдельного стартового гранта на главу: `T2–T5` начинаются так же, как
`T1`, с Molecular/RNA. Уже пройденный участок сжимается перками Archive
Recall (не пропускается), что освобождает время внутри растущего бюджета под
по-настоящему новый контент перед следующим, более поздним коллапсом. Игрок
должен видеть, что большая часть контента/находок ещё не открыта — это и есть
мотивация к следующей попытке, поэтому replay сжимается, а не скипается.
Задача этого документа — зафиксировать, что именно меняется от главы к главе
на уровне gameplay-контракта: где именно наступает коллапс (era cutoff),
сколько бюджета и сколько от него — уже виденный, сжатый Recall'ом участок, а
не заново пройденный.

# 2. Один принцип вместо четырёх новых систем

Каждая из глав `T1–T4` заканчивается новым типом коллапса (не `Ash`). Вместо
четырёх разных систем кризиса — **один переиспользуемый событийный паттерн**,
упрощённая версия того, что уже построено для Great Filter: одно authored
anomaly-событие, вводящее угрозу как факт («rising»), затем одно mandatory
choice-событие с тремя вариантами, которое определяет subtype/epitaph, но не
отменяет сам коллапс — и переход в ending. Не нужен отдельный player-facing
meter вроде `World Tension`: главы `T1–T4` короче `T5` на порядок, и полная
4-фазная (`C0–C4`) Stability-последовательность туда не помещается по темпу.
Каждая глава меняет только:

- тексты rising- и final-события;
- какие предыдущие решения главы (governance, automation-risk и т.п.) входят
  в условие final-события;
- финальный ending ID/title/subtype.

Ни одна из глав `T1–T4` не реализуется как отдельный bespoke crisis engine —
обе события используют тот же generic event/goal-контракт, что и остальные
authored события GDD (`08_EVENTS_AND_CHOICES.md`).

`T5` — единственная глава, которая использует буквально существующий полный
`Stability`/`World Tension`/`EV-CR-01..03` 4-фазный кризис почти без
изменений (см. §7) — она одна достаточно длинная (~40 мин), чтобы нести
такую последовательность.

этом исчерпан. Swap — косметика (лейблы, 1–2 flavor-способности); полная
глубина трейтов остаётся за Актом 3.

# 4. Точка входа: одна и та же для всех глав

Все пять глав входят в мир одинаково — `MOLECULAR` (RNA), пусто, как `T1`
сейчас. Разница глав не в старте, а в том, где именно наступает коллапс
(era cutoff, §3) и сколько от уже пройденного пути **сжато** Archive Recall
перками, а не проиграно заново в реальном времени:

| Глава | Recall-сжатый участок | Играется вживую, в реальном темпе |
|---|---|---|
| `T1` | нет | RNA → Tribe |
| `T2` | RNA → Tribe (`T1-0…T1-2`, Tribe-часть `T1-3`) | Settlement-часть `T1-3` → Cataclysm |
| `T3` | RNA → Settlement (`T1-0…T1-3`) | City-часть `T1-4` → Раскол |
| `T4` | RNA → City (`T1-0…T1-4`) | Industry/Modern-часть `T1-5` → Авария |
| `T5` | RNA → Industry/Modern (`T1-0…T1-5`) | Great Filter/Ash (`T1-6`) |

Реализация — не новый онбординг и не стартовый state-грант, а применение
уже открытых на предыдущих главах Archive Recall-перков (`docs/gdd/
10_META_PROGRESSION.md` §4 — с 2026-09-18 это набор перманентных, стакающихся
перков по выбору 1 из 3 на главу, а не единый автоматический множитель) к
диапазону, уже пройденному в предыдущих главах.
Экономика/дерево/здания остаются те же данные, что описаны в
`03_EVOLUTION_TREE.md`, `05_BUILDINGS_AND_JOBS.md`, `06_TECH_TREE.md` — новых
веток строить не нужно.

Это касается только **механического** контента (данные экономики/дерева
переиспользуются буквально). **Goal-чек-лист**, который видит игрок для
Recall-сжатого участка, — не тот же самый: см. §5 про свой, более крупный
набор целей на каждую главу.

# 5. Цели и вехи по главам

`G001–G024` (`07_GOALS_AND_MILESTONES.md`) остаётся canonical описанием
контента биологии/цивилизации, но **не** переигрывается goal-в-goal пятью
главами подряд — смотреть один и тот же 15-шаговый чек-лист от RNA до
Tribe пять раз подряд скучно. Вместо этого у каждой главы — **свой** набор
голов на Recall-сжатый участок, размеченный **крупнее**, чем у главы, что
покрывала этот участок раньше (меньше карточек, каждая шире), плюс пара
новых коротких Archive-реплик внутри этого куска, чтобы он не читался как
немое ускорение:

```text
T1: G001–G015 (полная нарезка, 15 шагов)         + G025 (rising), G026 (Мор, ending)
T2: свой recap RNA→Tribe (крупнее G001–G015)     + G027–G030 (Катаклизм, ending)
T3: свой recap RNA→Settlement (крупнее recap T2) + G031–G034 (Раскол, ending)
T4: свой recap RNA→City (крупнее recap T3)       + G035–G039 (Авария, ending)
T5: свой recap RNA→Industry/Modern (крупнее recap T4) + G020_T5/G022–G024 (Ash)
```

Огрубление начинается уже с `T2` (не только начиная с `T3` — recap уровня
`T1`'s собственных `G001–G015` тоже не переигрывается буквально). Каждый
recap — design scope, новые ID (не назначены, продолжают свободный диапазон
после `G039`), точное число шагов/огрубление по главам не финализировано.

Коллапс-цели предыдущих глав (`G025/G026` для `T1`, `G027–G030` для `T2` и
т.д.) не входят в recap следующей главы — это единственная причина, почему
`Мор`/`Катаклизм`/`Раскол`/`Авария` не срабатывают повторно: они просто не
часть чужого goal-набора, отдельного «уже пережил» флага не нужно. `G022–
G024` (Atomic-контент) — исключение: это по-настоящему новый для `T5`
контент (никакая более ранняя глава его живьём не проходит), поэтому он
переиспользуется как есть, без recap-огрубления. Точная, canonical нарезка
самого нового (не-recap) содержимого — `docs/gdd/07_GOALS_AND_MILESTONES.md`
§3–8:

```text
T1: G001–G015          + G025 (rising), G026 (Мор, ending)
T2: G027–G030          (G030 = Катаклизм, ending)
T3: G031–G034          (G034 = Раскол, ending; G032B governance входит в условие)
T4: G035–G039          (G039 = Авария, ending; G037 automation-risk входит в условие)
T5: G020–G024 (старая нумерация) + EV-NAR-08 intro, синтез-deck
```

Конкретные `targetTimeMs` пересчитываются под budget из §3 этого документа —
теперь измеряются от старта RNA конкретной попытки, а не от постгрантового
нуля, и не унаследованы от старой 180-минутной шкалы.

Каждая глава `T1–T4` добавляет один **collapse goal** (последний G в её
диапазоне выше), не являющийся `G0xx`-целью Sapience-цепочки. Формат
идентичен существующему `G024 Пройдите Великий фильтр`: не purchase-цель,
одно rising anomaly-событие → один mandatory choice → ending. Хорошая игра не
отменяет коллапс, только меняет subtype/reward/Chronicle — тот же hard rule,
что уже действует для `G024`/`Ash`.

Новые вехи (`MS`-серия продолжается с существующей `MS01–MS09`, которая не
перенумеровывается — см. `07_GOALS_AND_MILESTONES.md` §9 для полной таблицы
`MS10–MS15`):

| ID | Триггер | Title |
|---|---|---|
| `MS10` | `G026` ending | МОР |
| `MS11` | `G029` | ПЕРВЫЙ ТОЛЧОК |
| `MS12` | `G030` ending | КАТАКЛИЗМ |
| `MS13` | `G031` | КРЕПОСТЬ |

РАСКОЛОЛИ МАТЕРИЮ`), а не каждая последующая глава повторно.

# 6. Новые endings `T1–T4`

Все четыре используют общий, но **облегчённый** вариант паттерна `ENDING_ASH`
(`09_ENDINGS_AND_RESET.md` §16, `docs/scenario/06_ENDINGS_COPY.md` §0):
короткая пауза + локальное затемнение (без белой вспышки — она остаётся за
`Ash`), ending card, 1–2 строки Archive neutral summary, reveal-строка (если
у главы она есть), idempotent reset, CTA `Продолжить синтез` — никогда
`Game Over`/`Попробовать снова`. В отличие от `Ash`, они не показывают
полный многосекционный Archive Summary и ведут **в следующую главу Акта 1**,
а не в Timeline #2/Act 2 teaser (тот остаётся исключительно после `T5`).

| Глава | Ending ID | Title | Визуал коллапса | Archive Recall-награда |
|---|---|---|---|---|
| `T1` | `ENDING_BLIGHT` | МОР | диорама тускнеет, population-иконки гаснут по одной | выбор 1 из 3 T1-перков |
| `T2` | `ENDING_CATACLYSM` | КАТАКЛИЗМ | трещины/разлом ландшафта, диорама рушится | защитный перк (косметика) + выбор 1 из 3 T2-перков |
| `T3` | `ENDING_FRACTURE` | РАСКОЛ | диорама раскалывается на изолированные фрагменты | защитный перк (косметика) + выбор 1 из 3 T3-перков |
| `T4` | `ENDING_OVERLOAD` | АВАРИЯ | индустриальный skyline гаснет каскадом, как отказ сети | защитный перк (косметика) + выбор 1 из 3 T4-перков |
| `T5` | `ENDING_ASH` | ПЕПЕЛ (существующий) | белая вспышка (без изменений) | выбор 1 из 3 постоянных endgame-перков |

**Скорректировано 2026-09-18:** нет никакой валюты (AF или иной) в Act 1-2 —
единственная награда за каждый ending — Archive Recall перк. Оставшиеся
варианты каждой главы (и, для `T5`, оставшиеся endgame-перки) добираются
позже через Archive-mode replay, не в этом же первом прохождении. Точный
состав перков — `docs/gdd/10_META_PROGRESSION.md` §4.2/§4.4; точная
балансировка чисел внутри перков — предмет `ACT-006`/будущего DS.

Каждый non-Ash ending обязателен так же, как `Ash` был обязателен в старом
дизайне: это не failure state, а запланированный конец главы. Хорошая игра
внутри главы улучшает subtype/reward/Chronicle, не отменяет коллапс —
идентично правилу `09_ENDINGS_AND_RESET.md` §6.

# 7. `T5` — синтез: обязательный слой процедурных «эхо»-событий

`T5` реализуется почти без изменений (`T1-5…T1-6` package) — Modern bridge,
`ERROR 17`, Atomic Theory, `World Tension`/crisis C0–C4, `Last Protocol`,
`ENDING_ASH`, всё как в `08_EVENTS_AND_CHOICES.md`/`09_ENDINGS_AND_RESET.md`
сейчас. Единственное содержательное дополнение, которое требует эта
переделка — новый процедурный event-слой, дающий ощутимую, а не только
продекларированную в интро-строке, форму фразе «Архив смешивает уроки `T1–T4`».

## 7.1 Проблема

Процедурный (не authored) event deck сейчас существует только в самом начале
игры: `deck: 'early_biology'` (`EV-RNA-RESONANCE`, `EV-DNA-TRACE` в
`src/chronicles/config/events.js`) покрывает только molecular-окно. Every
other phase, включая весь Modern/Atomic диапазон, имеет только authored
one-off события — ни одного procedural minor/major deck, хотя
`12_LONG_TERM_PROGRESSION_AND_RESET_ROADMAP.md` §7 требует его для всего `T1`
целиком. Это именно то окно, которое теперь принадлежит `T5`.

## 7.2 Контракт `deck: 't5_synthesis'`

Тот же generic Event Engine, что уже обслуживает `early_biology`
(seeded weighted draw, per-event cooldown, save-сериализуемое deck state) —
новый набор карточек, не новый движок.

```text
window: Modern → Atomic (весь T5 после EV-NAR-08 «Синтез», до Last Protocol)
cadence: minor ~ раз в 2–4 мин; major доступна только после того, как её
  парная minor уже разыграна в этом прогоне (короче T5, поэтому пары
  «minor → major», а не отдельная global cadence)
each pair: precondition — meta.endings.chapterN_subtype установлен для
  соответствующей главы; если флаг отсутствует (глава пройдена иначе или
  save мигрировал без полной истории), пара не входит в eligible pool —
  никаких generic заглушек
effect: небольшой capped grant/Stability-adjacent bonus ИЛИ чистый
  Chronicle-flavor без numeric эффекта (minor карточки); major-карточки —
  explicit risk/reward choice, Chronicle-текст варьируется по конкретному
  subtype прошлой главы
hard rule: ни одна echo-карточка не может предотвратить обязательный первый
  Ash — тот же принцип, что уже действует для EV-CR-01/02
```

## 7.3 Набор карточек — четыре пары (minor + major), по одной на главу

| ID | Precondition | Type | Смысл |
|---|---|---|---|
