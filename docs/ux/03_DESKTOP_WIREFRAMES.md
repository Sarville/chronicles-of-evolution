# Хроники Эволюции — Настольные вайрфреймы

**Документ:** DS-06  
**Статус:** черновик, готов к ревью  
**Область:** desktop UX для «Линии времени №1»  
**Основание:** `02_MOBILE_WIREFRAMES.md`, принятые DS-05 и DS-05.5; `PB00–PB30`, `V0–V9`, `C0–C7`

---

# 1. Назначение

Настольная версия адаптирует мобильную иерархию, но не вводит отдельные правила игры. Игрок по-прежнему видит мир как главный контекст, текущую цель как главный навигационный объект и только те системы, которые уже раскрыты в Timeline #1.

Desktop layout должен использовать ширину экрана для постоянных панелей и сравнения информации, но сохранять мобильный порядок приоритетов:

1. диорама мира;
2. текущая цель;
3. контекстные ресурсы;
4. действие или фокусная система;
5. подробности, история и вторичные панели.

---

# 2. Базовый desktop shell

Опорный размер — `1366 × 768` CSS px. Макет должен устойчиво работать от `1024 × 640` до широких экранов. Ни один gameplay control не должен требовать hover-only взаимодействия.

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ СТАТУСНАЯ ПОЛОСА: эра / время / критический сигнал                         │ 48
├───────────────┬──────────────────────────────────────────────┬─────────────┤
│ ЛЕВАЯ ПАНЕЛЬ  │                                              │ ПРАВАЯ      │
│ ресурсы       │                                              │ ПАНЕЛЬ      │
│ цель          │                ДИОРАМА МИРА                  │ система     │
│ главное       │                                              │ фазы        │
│ действие      │                                              │             │
├───────────────┴──────────────────────────────────────────────┴─────────────┤
│ НИЖНЯЯ ПОЛОСА: журнал коротких сообщений / доступные вкладки / состояние    │ 56
└────────────────────────────────────────────────────────────────────────────┘
```

### Области

| Область | Роль | Поведение |
|---|---|---|
| Верхняя статусная полоса | Эра, время, редкие critical indicators | Не становится длинной строкой всех ресурсов |
| Левая панель | Current Goal, контекстные ресурсы, главное действие | При кризисе сжимается до цели и напряжения |
| Диорама | Главная сцена мира | Остаётся крупнейшей областью до `SCR_ENDING` |
| Правая панель | «Эволюция», работы, здания, энергия, хроника или событие | Меняет содержимое по фазе; закрывается до узкой вкладки |
| Нижняя полоса | Короткие сообщения Архива, события, recent feedback | Не заменяет «Хронику» и не копит все тики |

Минимальная ширина диорамы на desktop — 48% viewport. Если панели открыты и экран узкий, первой сворачивается правая панель, затем нижняя полоса, но не карточка текущей цели.

# 3. D-00 — зарождение и первая клетка

**Покрытие:** `PB00–PB06`  
**Поверхности:** `SCR_BOOT`, `SCR_WORLD`, `SCR_MILESTONE`, `SCR_EVOLUTION`  
**Состояния:** `V0_PRIMORDIAL` → `V1_CELLULAR`, `C0` → `C2_CELL`

```text

│ ПЕРВОБЫТНЫЙ ОКЕАН                                             00:02        │
├─────────────────┬────────────────────────────────────────────┬─────────────┤
│ СОБРАТЬ ПЕРВУЮ  │                                            │ ЭВОЛЮЦИЯ    │
│ ЦЕПЬ            │       живая химическая среда                │ скрыта до   │
│ РНК 3 / 5       │       реакция / ритм / мембрана             │ PB03        │
│                 │                                            │             │
```

- `PB00–PB02`: правая панель отсутствует или свернута. Экран не должен выглядеть как пустая dashboard-сетка.
- `PB03`: правая панель открывается как «Эволюция» и показывает только актуальный биологический узел. AP, «Познание», работы и кризисные системы отсутствуют.
- `PB04`: во время замыкания мембраны левая панель приглушается до outline, диорама получает максимум внимания.
- `PB05`: `SCR_MILESTONE` перекрывает все панели на 2–4 секунды. После него левая панель возвращается с Biomass context.
- `PB06`: «Энергия» появляется в левой панели как ресурс метаболизма, не в глобальном header до своего gameplay relevance.

# 4. D-01 — ветвь клетки и организм

**Покрытие:** `PB07–PB14`  
**Поверхности:** `SCR_WORLD`, `SCR_EVOLUTION`, `SCR_EVENT`, `SCR_MILESTONE`  
**Состояния:** `V1_CELLULAR` → `V2_CREATURE`, `C2_CELL` → `C4_MULTICELLULAR_ORGANISM`

## 4.1. Выбор ветви

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ КЛЕТОЧНАЯ ЖИЗНЬ                                                12:40       │
├─────────────────┬────────────────────────────────────────────┬─────────────┤
│ ВЫБЕРИТЕ ПУТЬ   │       клетка + три live-preview             │ ВЫБОР ВЕТВИ │
│ МЕТАБОЛИЗМА     │       вокруг текущей формы                  │             │
│                 │                                            │ Поглощение  │
│ Энергия 4/6     │                                            │ Симбиоз     │
│ Биомасса 2/4    │                                            │ Оболочка    │
│                 │                                            │             │
│                 │                                            │ [ ВЫБРАТЬ ] │
└─────────────────┴────────────────────────────────────────────┴─────────────┘
```

- На desktop branch choice живёт в правой панели, а не в центральном modal, чтобы диорама могла показывать preview.
- Выбранный вариант подсвечивает соответствующую проекцию на диораме и краткое следствие в правой панели.
- Подтверждение фиксирует primary trait; дальнейшие адаптации не должны визуально стирать этот выбор.

## 4.2. AP и организм

- `PB09`: AP впервые появляется в статусной полосе или левой панели рядом с «Эволюцией». До `PB09` ни header, ни правая панель не резервируют AP-slot.
- Правая панель «Эволюция» показывает trunk node, optional AP adaptations и preview части тела. Она не превращается в полный graph редактор.
- `PB10`: milestone «МНОГОКЛЕТОЧНОСТЬ» временно скрывает обе панели, затем возвращает shell уже с `V2_CREATURE`.
- `PB12`: Cognition meter появляется только после Nervous System. На desktop он может жить в левой панели под целью; в header попадает только в компактной форме, если это главный phase signal.
- `PB14`: после Sapience биологические control rows уходят в «Эволюция / история вида», а левая панель переключается на Food / Materials / Knowledge / Population.

# 5. D-02 — племя, город, индустрия и современность

**Покрытие:** `PB15–PB24`  
**Поверхности:** `SCR_WORLD`, `SCR_EVENT`, `SCR_MILESTONE`, `SCR_CHRONICLE`

```text
│ Труд 2/3        │                                            │ Знание 0    │
│                 │                                            │             │
│ [ ПОСТРОИТЬ ]   │                                            │ [ + / - ]   │
├─────────────────┴────────────────────────────────────────────┴─────────────┤
│ Архив: появилась первая устойчивая запись.                                  │
└────────────────────────────────────────────────────────────────────────────┘
```

### Работы и здания

- Правая панель становится устойчивым рабочим пространством: «Работы», «Здания», «Хроника», а позже «Энергия».
- Jobs panel использует строки с назначенными группами, stepper controls и visible free groups. Массовая таблица всех ресурсов не нужна.
- Buildings panel показывает доступные постройки текущей фазы, цену, эффект на текущую цель и очередь, если очередь уже разблокирована.
- `PB18` «Следы до нас» открывается как event panel справа с объектом на диораме. Для необратимого выбора может включаться focused confirm, но мир остаётся видимым.

### Энергия и Modern

- `PB20`: механизация может добавить новые строки работ и здания, но не активный ресурс Power.
- `PB21`: milestone «ЭПОХА МАШИН» завершает первое появление Power. После этого правая панель получает вкладку «Энергия».
- `PB22`: энергетический кризис использует правую event panel с preview-переключением на диораме. Выбор должен показывать persistent modifier до подтверждения.
- `PB23`: Modern расширяет диораму до regional/world-scale view. Shell остаётся тем же, чтобы масштаб мира ощущался как рост, а не новый экран.
- `PB24`: ERROR 17 отображается в обычном header/current-goal flow. Он не открывает отдельную страницу и не прерывает управление, пока gameplay не переводит игрока к Atomic/crisis.

**Покрытие:** `PB25–PB27`  
**Поверхности:** `SCR_MILESTONE`, `SCR_CRISIS`, `SCR_EVENT`  
**Состояние:** `V8_ATOMIC`

```text
│ КРИТИЧЕСКАЯ     │                                            │ КРИЗИС      │
│ ФАЗА            │          V8 world with crisis overlays      │             │
│                 │                                            │ События     │
```

- `PB27`: Last Protocol использует сфокусированный overlay по центру с затемнёнными боковыми панелями. После подтверждения панели блокируются, диорама остаётся видимой, затем следует flash.

# 7. D-04 — «Пепел», «Архив» и новый запуск

**Покрытие:** `PB28–PB30`  
**Поверхности:** `SCR_ENDING`, `SCR_ARCHIVE`, `SCR_META`  
**Состояние:** `V9_ASH`

## 7.1. Ending

```text
┌────────────────────────────────────────────────────────────────────────────┐
│                                                                            │
│                  пепельная версия собственного V8 мира                      │
│                                                                            │
│                     ЦИВИЛИЗАЦИЯ №1 ЗАВЕРШЕНА                                │
│                                ПЕПЕЛ                                        │
│                                                                            │
│                         [ СОХРАНИТЬ В АРХИВ ]                               │
└────────────────────────────────────────────────────────────────────────────┘
```

На `SCR_ENDING` нет header, goal card, ресурсов, jobs panel или обычной навигации. Это результат истории, а не кризисный экран.

## 7.2. Archive summary

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ АРХИВ                                                                      │
├──────────────────────────────┬─────────────────────────────────────────────┤
│ миниатюра V9 мира             │ ЛИНИЯ ВРЕМЕНИ №1                            │
│ вид / primary trait           │ Вид и адаптации                             │
│ путь цивилизации              │ Путь цивилизации                            │
│ финал                         │ Ключевые решения                            │
│                               │ Кризис и финал                              │
│                               │ Фрагменты Архива                            │
├──────────────────────────────┴─────────────────────────────────────────────┤
│                                                        [ ПРОДОЛЖИТЬ ]       │
└────────────────────────────────────────────────────────────────────────────┘
```

- Archive summary использует ширину desktop для двух колонок: слева визуальная запись мира и краткие anchors, справа разворачиваемая история.
- Порядок секций совпадает с mobile: вид → цивилизация → решения → кризис → Archive fragments.
- Это не score screen: числа поддерживают историю, а не оценивают игрока.

## 7.3. Archive memory

`PB30` может использовать центрированный full-screen layout: запись Timeline #1 остаётся как объект в пространстве Архива, заголовок `АРХИВ ПОМНИТ`, строка `Мы можем изменить результат.` и CTA `СОЗДАТЬ НОВУЮ ЖИЗНЬ`.

# 8. Responsive breakpoints

| Диапазон | Поведение |
|---|---|
| `< 768 px` | Использовать мобильный portrait shell из `02_MOBILE_WIREFRAMES.md` |
| `768–1023 px` | Tablet hybrid: одна боковая панель, вторичные детали как sheet |
| `1024–1439 px` | Standard desktop: левая панель + диорама + правая панель |
| `>= 1440 px` | Wide desktop: диорама расширяется первой; панели не становятся чрезмерно широкими |

Максимальная ширина левой панели — 320 px, правой — 360 px. На wide screens дополнительное место получает диорама и camera breathing room, а не новые постоянные виджеты.

# 9. Сводка покрытия

| Desktop вайрфрейм | Биты | Главная задача |
|---|---|---|
| D-00 | `PB00–PB06` | Сохранить ранний экран тихим и диорама-first |
| D-01 | `PB07–PB14` | Дать место branch/AP/Cognition без premature UI |
| D-02 | `PB15–PB24` | Перевести shell к jobs/buildings/Power/Modern |
| D-03 | `PB25–PB27` | Сжать интерфейс вокруг World Tension и crisis events |
| D-04 | `PB28–PB30` | Завершить историю через full-screen Ending и Archive |

Desktop версия является responsive adaptation той же UX-иерархии, что и mobile, и не добавляет новых gameplay или narrative beats.
